STEP 0.1 — INSTALL GOOGLE CLOUD CLI (gcloud) ON YOUR MACHINE
------------------------------------------------------------------------

WHY: gcloud is the command-line tool to talk to GCP from your computer.
     You will use this to create buckets, deploy services, etc.

HOW:
  1. Open your browser and go to:
     https://cloud.google.com/sdk/docs/install

  2. Download the Windows installer (you are on Windows).
     It will be a file named something like:
     GoogleCloudSDKInstaller.exe

  3. Run the installer. Click Next on everything.
     When it asks to run "gcloud init" at the end — say YES.

  4. A browser window will open. Sign in with your Google account.
     This links your Google account to gcloud on your machine.

  5. When it asks "Pick cloud project to use" — skip for now.
     We will set this later.

  6. Close and reopen your terminal (PowerShell or CMD).

  7. Test it worked by running:
     gcloud --version
     You should see version numbers printed. If you see an error,
     the installation failed — redo step 3.

  every time you do anything with Docker. Keep it open.

STEP 1.3 — CREATE A SERVICE ACCOUNT
----------------------------------------------------------------------

WHY: A service account is like a robot identity.
     GitHub Actions will use it to push Docker images to GCP
     and deploy your app. It needs permission to do those things.

  In PowerShell, run these commands ONE BY ONE:

  COMMAND 1 — Create the service account:
    gcloud iam service-accounts create apu-deploy-sa \
      --display-name="APU Deploy Service Account"

  COMMAND 2 — Give it Cloud Run permission:
    gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
      --member="serviceAccount:apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
      --role="roles/run.admin"

  COMMAND 3 — Give it Artifact Registry permission:
    gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
      --member="serviceAccount:apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
      --role="roles/artifactregistry.writer"

  COMMAND 4 — Give it Storage permission:
    gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
      --member="serviceAccount:apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
      --role="roles/storage.admin"

  COMMAND 5 — Give it Cloud SQL permission:
    gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
      --member="serviceAccount:apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
      --role="roles/cloudsql.client"

  COMMAND 6 — Give it Secret Manager permission:
    gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
      --member="serviceAccount:apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
      --role="roles/secretmanager.secretAccessor"

  COMMAND 7 — Give it Service Account User permission (needed for deployments):
    gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
      --member="serviceAccount:apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
      --role="roles/iam.serviceAccountUser"

  Replace YOUR_PROJECT_ID with your actual project ID in every command.

  VERY IMPORTANT SECURITY RULES:
  - NEVER commit this file to GitHub.

  - NEVER put it inside your project folder.
  - Store it somewhere safe like Desktop or Documents.
  - If you accidentally commit it — delete it from GitHub immediately

  Open the file in Notepad. It looks like a big JSON starting with:

STEP 3.1 — CREATE GCS BUCKETS
----------------------------------------------------------------------

WHY: Two buckets needed.
     Bucket 1 (apu-model-artifacts): stores your model, scaler, config.
     Bucket 2 (apu-incoming-data): stores every CSV users upload.

  In PowerShell:

  COMMAND 1 — Create model artifacts bucket:
    gsutil mb -p YOUR_PROJECT_ID -l us-central1 gs://apu-model-artifacts-YOUR_PROJECT_ID/

  COMMAND 2 — Create incoming data bucket:
    gsutil mb -p YOUR_PROJECT_ID -l us-central1 gs://apu-incoming-data-YOUR_PROJECT_ID/

  NOTE: GCS bucket names must be globally unique across ALL of GCP.
  Adding your project ID at the end ensures uniqueness.
  Example: gs://apu-model-artifacts-apu-predictive-maintenance-123456/

  Verify buckets were created:
    gsutil ls
  You should see both bucket names listed.

STEP 3.2 — UPLOAD MODEL FILES TO GCS
----------------------------------------------------------------------

WHY: The Docker container does NOT contain the model files.
     The Flask app downloads them from GCS when it starts up.
     If these files are not in GCS, the app crashes on startup.

  Make sure you are in your project root with venv activated:
    cd E:\APU_Predictive_Maintenance
    .APU_venv\Scripts\activate

  First, run training to make sure baseline_stats.json exists
  (Antigravity added baseline stats generation to training pipeline):
    python entrypoint/training.py

  Now upload the 3 required files:

  COMMAND 1:
    gsutil cp Artifacts/Model/model_LGBM.pkl gs://apu-model-artifacts-YOUR_PROJECT_ID/model_LGBM.pkl

  COMMAND 2:
    gsutil cp Artifacts/Scaler/scaler.pkl gs://apu-model-artifacts-YOUR_PROJECT_ID/scaler.pkl

  COMMAND 3:
    gsutil cp Artifacts/baseline_stats.json gs://apu-model-artifacts-YOUR_PROJECT_ID/baseline_stats.json

  Verify all 3 files are there:
    gsutil ls gs://apu-model-artifacts-YOUR_PROJECT_ID/
  You should see:
    gs://apu-model-artifacts-YOUR_PROJECT_ID/baseline_stats.json
    gs://apu-model-artifacts-YOUR_PROJECT_ID/model_LGBM.pkl
    gs://apu-model-artifacts-YOUR_PROJECT_ID/scaler.pkl

STEP 3.3 — CREATE CLOUD SQL DATABASE
----------------------------------------------------------------------

WHY: Every prediction your app makes gets stored here.
     This is needed for drift detection in Phase 5.

  COMMAND 1 — Create the database instance:
    (This takes 5-7 minutes. Be patient.)

    gcloud sql instances create apu-db \
      --database-version=POSTGRES_14 \
      --tier=db-f1-micro \
      --region=us-central1 \
      --storage-size=10GB \
      --storage-type=SSD \
      --no-backup

    db-f1-micro is the cheapest tier. It costs about $7/month.
    For a project this size it is perfectly fine.

  COMMAND 2 — Create the database:
    gcloud sql databases create apu_predictions --instance=apu-db

  COMMAND 3 — Create a database user:
    gcloud sql users create apu_user \
      --instance=apu-db \
      --password=APU_StrongPassword_2026

    WRITE DOWN THIS PASSWORD. You need it in the next step.
    Use a strong password — do not use the example above.

  COMMAND 4 — Get the database connection name:
    gcloud sql instances describe apu-db --format="value(connectionName)"
    This prints something like:
    apu-predictive-maintenance-123456:us-central1:apu-db
    WRITE THIS DOWN. It is your DB_CONNECTION_NAME.

  COMMAND 5 — Get the public IP of the database:
    gcloud sql instances describe apu-db --format="value(ipAddresses[0].ipAddress)"
    WRITE DOWN THIS IP ADDRESS. It is your DB_HOST.

STEP 4.2 — CREATE THE CLOUD RUN JOB
----------------------------------------------------------------------

WHY: A Cloud Run Job is a one-off container that runs and exits.
     It is different from the Cloud Run Service (which runs continuously).
     The retraining job runs once a week, does its work, then stops.

  Antigravity writes infra/setup_scheduler.sh with the exact commands.
  YOU run those commands in PowerShell:

  COMMAND 1 — Create Cloud Run Job:
    gcloud run jobs create apu-retrain-job \
      --image us-central1-docker.pkg.dev/YOUR_PROJECT_ID/apu-repo/apu-retrain:latest \
      --region us-central1 \
      --service-account apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com \
      --set-env-vars GCS_MODEL_BUCKET=apu-model-artifacts-YOUR_PROJECT_ID,GCS_DATA_BUCKET=apu-incoming-data-YOUR_PROJECT_ID,GCP_PROJECT_ID=YOUR_PROJECT_ID

  COMMAND 2 — Test run the job manually ONCE to verify it works:
    gcloud run jobs execute apu-retrain-job --region us-central1 --wait

    This will run retrain.py right now.
    Watch the output. At the end you should see something like:
    "No new data found. Skipping retraining."
    That is CORRECT — there is no new data yet. The job ran successfully.

    If it says ERROR — check the logs:
    gcloud run jobs executions list --job=apu-retrain-job --region=us-central1
    Copy any errors to Antigravity.

STEP 4.3 — CREATE CLOUD SCHEDULER
----------------------------------------------------------------------

WHY: This is the cron job that triggers retraining every Sunday midnight.

  COMMAND:
    gcloud scheduler jobs create http apu-weekly-retrain \
      --location us-central1 \
      --schedule "0 0 * * 0" \
      --uri "https://us-central1-run.googleapis.com/apis/run.googleapis.com/v1/namespaces/YOUR_PROJECT_ID/jobs/apu-retrain-job:run" \
      --message-body "{}" \
      --oauth-service-account-email apu-deploy-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com \
      --time-zone "UTC"

  "0 0 * * 0" means: at midnight (0:00) every Sunday.

  Verify it was created:
    gcloud scheduler jobs list --location us-central1
  You should see "apu-weekly-retrain" listed with status ENABLED.
